# 콘서트 예약 시스템 요구사항

## 시스템 개요
콘서트 좌석 예약을 위한 대기열 기반 예약 시스템으로, 공정한 선착순 처리와 동시성 제어를 제공합니다.

---

## 1. 대기열 시스템

### 1.1 기본 정책
- **입장 속도**: 10초마다 10명씩 입장 처리
- **대기 순서**: FIFO (First In First Out) - 요청 순서대로 대기열 순번 부여
- **최대 동시 입장 인원**: 500명
  - **입장 처리 조건**: 현재 입장되어 있는(ACTIVE 상태) 사용자가 500명 이하일 때만 대기열에서 입장 처리 진행
  - **입장 처리 방식**:
    - 입장된 인원이 500명 이하이면 10초마다 10명씩 대기열에서 입장 (대기열 감소)
    - 입장된 인원이 500명 초과이면 대기열 입장 처리 중단 (대기열 유지)
  - **즉시 입장**: 대기열이 비어있고 입장된 인원이 500명 미만이면 토큰 발급 시 즉시 ACTIVE 상태로 발급

### 1.2 토큰 관리
- **토큰 생성**: UUID 기반 문자열
- **토큰 유일성**: 각 사용자당 하나의 유일한 토큰 보유
- **토큰 만료 시간**:
  - 대기열 대기 중(WAITING 상태): 만료 없음 (무한 대기 가능)
  - 입장 후(ACTIVE 상태): 30분
    - 입장 시점부터 30분 동안 좌석 조회, 예약, 결제 가능
    - 30분 경과 시 토큰 자동 만료 및 임시 예약 좌석 해제
- **토큰 유효 범위**: 대기열 통과 및 좌석 예약/결제 전 과정에서 유효

### 1.3 토큰 검증
- 모든 좌석 조회/예약/결제 API 요청 시 토큰 검증 필수
- 토큰이 만료되었거나 유효하지 않으면 에러 반환

## 2. 좌석 예약 시스템

### 2.1 좌석 상태
| 상태 | 설명 |
|------|------|
| `AVAILABLE` | 예약 가능한 상태 |
| `TEMP_RESERVED` | 임시 예약 상태 (결제 대기 중) |
| `CONFIRMED` | 예약 확정 상태 (결제 완료) |

### 2.2 좌석 상태 전환
```
AVAILABLE → TEMP_RESERVED → CONFIRMED
```

- **AVAILABLE → TEMP_RESERVED**
  - 사용자가 좌석 예약 API 호출 시 발생
  - 임시 점유 시간: **5분**
  - 5분 내 결제하지 않으면 자동으로 AVAILABLE로 복원

- **TEMP_RESERVED → CONFIRMED**
  - 결제 완료 시 발생
  - 예약 확정 후 대기열 토큰 만료 처리

### 2.3 예약 제약 조건
- **동시 예약 방지**: 같은 좌석에 대해 동시에 여러 사용자가 예약할 수 없음
- **토큰 검증**: 유효한 토큰을 가진 사용자만 예약 가능
- **임시 예약 제한**: 한 사용자가 여러 좌석을 동시에 임시 예약할 수 없음 (선택 사항)

## 3. 결제 시스템

### 3.1 결제 프로세스
1. 임시 예약된 좌석(TEMP_RESERVED)에 대해 결제 요청
2. 사용자 잔액 확인
3. 포인트 및 현금 차감
4. 좌석 상태를 CONFIRMED로 변경
5. 대기열 토큰 만료 처리
6. 결제 내역 저장

### 3.2 잔액 차감 정책
- **포인트 사용 플래그**: 사용자가 포인트 사용 여부를 선택할 수 있음
- **포인트 사용 시**: 포인트 사용 플래그가 true일 경우, 보유 포인트를 먼저 차감하고 남은 금액을 현금에서 차감
- **포인트 미사용 시**: 포인트 사용 플래그가 false일 경우, 전액 현금으로 결제
- **잔액 부족**:
  - 포인트 사용 시: 총 잔액(포인트 + 현금)이 부족하면 결제 실패
  - 포인트 미사용 시: 현금이 부족하면 결제 실패

**차감 순서 예시 (포인트 사용 플래그 = true):**
```
결제 금액: 10,000원
보유 포인트: 3,000원
보유 현금: 8,000원
포인트 사용: true

→ 포인트 3,000원 차감 (잔여: 0원)
→ 현금 7,000원 차감 (잔여: 1,000원)
→ 결제 성공
```

**차감 순서 예시 (포인트 사용 플래그 = false):**
```
결제 금액: 10,000원
보유 포인트: 3,000원
보유 현금: 8,000원
포인트 사용: false

→ 현금 10,000원 차감 시도 (잔여: -2,000원)
→ 현금 부족으로 결제 실패
```

### 3.3 포인트 적립 정책
- **적립률**: 결제 금액의 5%
- **적립 시점**: 결제 완료 즉시
- **적립 대상**: 현금으로 결제한 금액에 대해서만 적립 (포인트 사용분 제외)

**적립 예시:**
```
결제 금액: 10,000원
포인트 사용: 3,000원
현금 사용: 7,000원

→ 적립 포인트: 7,000원 × 5% = 350원
```

## 4. API 엔드포인트 (예상)

### 4.1 대기열 API
- `POST /v1/queue/token` - 대기열 토큰 발급
- `GET /v1/queue/status` - 현재 대기 순서 조회

### 4.2 좌석 API
- `GET /v1/seats` - 예약 가능한 좌석 목록 조회 (토큰 필수)
- `POST /v1/seats/reserve` - 좌석 임시 예약 (토큰 필수)

### 4.3 결제 API
- `POST /v1/payment` - 결제 처리 (토큰 필수)

## 5. 에러 처리

### 5.1 주요 에러 케이스
| 에러 코드 | 상황 | 메시지 |
|----------|------|--------|
| `TOKEN_EXPIRED` | 토큰 만료 | "토큰이 만료되었습니다." |
| `TOKEN_INVALID` | 유효하지 않은 토큰 | "유효하지 않은 토큰입니다." |
| `SEAT_NOT_AVAILABLE` | 좌석이 이미 예약됨 | "해당 좌석은 예약할 수 없습니다." |
| `INSUFFICIENT_BALANCE` | 잔액 부족 | "잔액이 부족합니다." |
| `RESERVATION_NOT_FOUND` | 예약 정보 없음 | "예약 정보를 찾을 수 없습니다." |
| `TEMP_RESERVATION_EXPIRED` | 임시 예약 시간 초과 | "임시 예약 시간이 만료되었습니다." |

## 6. 비기능 요구사항

### 6.1 성능
- 대기열 순번 조회: 100ms 이내
- 좌석 예약 처리: 200ms 이내
- 결제 처리: 500ms 이내

### 6.2 동시성
- 좌석 예약 시 동시성 제어 (낙관적/비관적 락)
- 잔액 차감 시 트랜잭션 격리 레벨 보장

### 6.3 데이터 저장
- **Redis**: 대기열 정보, 활성 토큰 (휘발성 데이터)
- **RDB**: 사용자, 좌석, 예약, 결제 내역 (영구 데이터)1

## 7. 추가 고려사항

### 7.1 임시 예약 만료 처리
- 스케줄러를 통해 주기적으로 5분 경과된 TEMP_RESERVED 좌석을 AVAILABLE로 복원

### 7.2 토큰 만료 처리
- WAITING 상태 토큰은 만료되지 않음 (무한 대기)
- ACTIVE 상태 토큰은 활성화 시점으로부터 30분 후 자동 만료
- Redis TTL을 활용하여 ACTIVE 토큰의 만료 시간 자동 관리
- 만료된 토큰으로 요청 시 `TOKEN_EXPIRED` 에러 반환
- 토큰 만료 시 해당 사용자의 임시 예약 좌석 자동 해제

### 7.3 대기열 입장 처리
- 스케줄러를 통해 10초마다 대기열에서 10명씩 활성 상태(ACTIVE)로 전환
- **실행 조건**: 현재 입장되어 있는(ACTIVE 상태) 사용자 수가 500명 이하일 때만 실행
- 입장된 인원이 500명 초과 시 스케줄러는 대기열 처리를 건너뛰고 다음 주기까지 대기
